# 底层元件焊盘坐标：离线解析与铜皮不一致（候选）

**日期**：2026-11-06 　**状态**：待验证（需要 API 焊盘坐标对账） 　**影响**：所有依赖离线焊盘坐标的几何检查

## 结论

在样本工程「关灯神器」上，`src/extract.py` 给出的底层 LED（U7、U8，`angle=0`，`layer=2`）焊盘坐标与 PCB 铜皮的网名对不上：按离线坐标，`PAD_NET` 说属 `TP4056_VCC` 的焊盘，落在铜皮上属于另一个网的焊盘位置。

**目前不能判定是「离线镜像变换错」还是「板子本身短路」。** 两者都会产生同样的现象，必须用 API 的焊盘 `x/y/net` 对账才能区分。

## 证据（只读，未改任何文件）

工程：`ProPrj_【DIY电子】关灯神器_2026-09-12.epro2`，editor 3.2.186。

1. **封装局部坐标**（`pcb.json.footprints["d397dbb13f575f47"]`，`LED-TH_BD4.0-P2.50-RD`）：
   - pad `2`（header `e15`）：`x=+49.21 mil`，`y=0`
   - pad `1`（header `e16`）：`x=−49.21 mil`，`y=0`

2. **`.epro2` 原始 `PAD_NET`**（U7 组件 id `395f804e5b01bd91`）：
   - `["PAD_NET","395f804e5b01bd91","2","e15"]` → `padNet = TP4056_VCC`
   - `["PAD_NET","395f804e5b01bd91","1","e16"]` → `padNet = $1N53`

3. **元件实例**：U7/U8 均为 `x=2742.9`、`angle=0`、`layer=2`（Bottom）。`extract.py` 对底层做「局部 x 取反」，得到：
   - pad `2`（e15）→ `x=2693.69`（左）
   - pad `1`（e16）→ `x=2792.11`（右）

4. **铜皮**（原始 `LINE` 记录，已核实 `netName`）：
   - `4491bfc839b4915d`：`netName=TP4056_VCC`，`(2792.11,−1255) → (2792.11,−1095)`，layer 2
     —— 正好连接 U7 pad 1 与 U8 pad 1 的位置。
   - `$1N53` 的走线终点在 `(2693.69,−1255)`，即 U7 pad 2 的位置。

5. 也就是说：**离线坐标下，右侧焊盘是 pad 1（`$1N53`），但铜皮右侧是 `TP4056_VCC`**；左侧同理相反。

## 两种解释

| 解释 | 含义 | 如何验证 |
|---|---|---|
| A. 离线镜像变换错 | 底层元件不应做「局部 x 取反」，或镜像轴/顺序与实现不同 | API 读 U7 的 pad `1/2` 的 `x/y`，与离线坐标逐点比 |
| B. 板子本身短路 | `TP4056_VCC` 走线压到 `$1N53`/`$1N54` 焊盘 | API 焊盘坐标 + EasyEDA DRC；网表不会报（网表只记归属，不看铜皮几何） |

## 已排除的干扰

- 不是 `PAD_NET` 解析错：原始记录与 `pcb.json` 的 `num/net` 完全对应。
- 不是走线网名解析错：直接读原始 `LINE` 记录，`netName` 就是 `TP4056_VCC`。
- 不是「封装焊盘号重复」问题：该封装只有两个焊盘，`e15/e16` 各一个。

## 对审核方式的影响

1. 新增前置检查 **A-04：离线焊盘坐标 vs API 焊盘坐标，逐点 `|Δ| ≤ 1 mil`**。
2. 未通过 A-04 的元件，其间距、连通性、去耦距离、EMC 几何检查一律只出「候选」，不出「已确认」。
3. 之前的结论「PCB 镜像语义 = 局部 x 取反」来自焊盘—走线吻合率的统计（Candis 146/280、关灯神器 34/101），不是逐点证明。本发现说明该结论至少不是对所有封装/角度都成立，**需要按工程、按封装复核**。
