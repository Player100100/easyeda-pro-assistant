# 多板系统联合审核

多板工程先逐板审核，再按**实际装配关系**做系统级联合审核。逐板网表、板内供电/时序/PCB几何各自保留边界；只有由已确认的连接器针脚、线束/背板映射或明确的板间设计记录支持时，才把网络和器件纳入跨板分析。

## 推荐实施方式

1. **固定对象与版本**：列出同一系统中的板卡实例、板卡版本、`.epro2`/独立设计文件哈希、BOM/装配变体、固件配置及审核时间。区分“板卡设计”与“装入系统的实例”；同一种板卡装入多次时，每个实例要有独立 ID。
2. **逐板取证**：每块 PCB 独立保存原理图、PCB、BOM、API 读数、规则、DRC/ERC 和覆盖率。为每块板确认对应的原理图页和 PCB 文档，不以元件最多的 PCB 代表整个工程。
3. **建立连接模型**：用机器可读的 `system-interconnect.json` 记录板卡实例、连接器、线束/背板和逐针脚映射。每条映射标成 `confirmed`、`inferred` 或 `unknown`，并记录来源；连接器针脚的定义与实际线束导通关系分开记录。
4. **按证据合并电气网络**：只把有证据证明导通的端点归入同一个系统网络。相同网名只是待核线索；同名不证明导通，不同名也不证明隔离。未确认的关系作为独立假设分析，报告中标 `REVIEW`/`NOT_CHECKED`，不得用于覆盖率或 PASS。
5. **分层分析并复核**：先逐板检查，再检查连接器和线束映射、跨板电源树与回流、信号方向/电平/上拉终端、隔离边界、接地/屏蔽、热插拔和上电时序、单点故障及系统工况。由未参与板内判断的 reviewer 复核关键跨板风险与覆盖率。

## 连接记录规则

- `board_instances[].id` 是系统装配实例 ID，不是 EasyEDA 文档 UUID。设计 UUID、文件哈希和实例 ID 分开记录。
- 一个端点由 `board_instance_id + connector + pin` 唯一定位。连接器针脚号按实际 mating view/厂商图纸解释，记录视角和证据；不可只靠图纸上看起来的左右位置推定。
- `interconnects[].connections[].endpoints` 表示经指定线束/背板互连的针脚集合。两端点用于点到点连接；多端点网络须注明星形/共节点等拓扑。重复端点或跨映射重复使用一个针脚须逐条核对；确有分支时写明共节点依据，不得隐式短接。
- 连接器/线束的设计映射、实物线束测试、装配配置属于不同证据。分别记录线号/线束版本、端到端导通或绝缘测试、未装/可选连接，以及测试条件。
- 对电源记录电压范围、连续/峰值电流、启动/瞬态负载、线长/线规/接触电阻和返回路径；对信号记录方向、逻辑电平/容限、速率/边沿、终端/偏置、保护、隔离及参考地。缺项保留未知，不从网名猜。
- 只有审查中使用的系统 BOM、配置和线束定义一致时，跨板结论才适用于该装配。多种配置分别建模并报告适用范围。
- 工况中的 `active_board_instances` 表示上电/工作的实例，`connected_interconnects` 表示物理接通的线束。未上电的板仍可通过接通的线束产生回灌，不能从网络分析中直接删除；部分针脚插拔、跳线或继电器切换需另建明确配置，不把一个静态映射套到全部工况。
- `source.status` 只表示证据确认程度，不表示电气审核 PASS。`confirmed` 至少有一条可追溯引用，且须人工核实引用支持该对象；模板中的 `unknown`、待填文本、`null` 哈希均不能作为已冻结输入。参数缺失表示未知，不等于 0。

## 系统级检查与覆盖

| ID | 检查内容 | 覆盖单位与证据 |
|---|---|---|
| MB-01 | 实例/版本、原理图归属、端点有效性和逐针脚映射 | 板卡实例、连接器全部针脚和线束导体；未用/屏蔽/壳体/机械脚显式记录处置，遗漏不是 NC |
| MB-02 | 跨板供电、负载预算、接触/线缆压降与回流 | 电源路径×工况；关联 C-11 的持续、瞬态、恢复预算及连接器额定条件 |
| MB-03 | 信号电平/容限、方向、总线终端/上拉及差分配对 | 接口×工况；厂商手册、实际阻值/终端、边沿和线缆条件 |
| MB-04 | 上下电、掉电回灌、热插拔及故障工况 | 接口/电源路径×工况；未供电容限、保护路径与时序依据 |
| MB-05 | 地、屏蔽、隔离边界与线束装配 | 边界/连接器/线束；隔离要求、接地方案、观察面和实测线序 |

每项沿用 v2 的 `PASS / FAIL / REVIEW / NOT_CHECKED / NOT_APPLICABLE`，统计适用总数、已执行、可判定、缺数据、不适用及原因。模型中列出的导体数不是完整工程的分母，须与连接器全部针脚和线束图核对；系统范围未知时不写 100%。定位使用 `系统/配置/板卡实例/连接器/针脚`，并关联线束 ID、线号和工况。逐板报告与系统报告分别列覆盖，不能用所有单板 DRC 为零推导系统通过。

## 当前工具边界

`.epro2` 提取器会保留每块 PCB 的数据，但目前的原理图网表是全工程汇总，自动的原理图↔PCB 对比只选择元件最多的那块 PCB；重复位号可能在汇总键中碰撞。因此多板项目不得把默认 `netlist.json` comparison 当作逐板一致性结论，也不得把 PCB 网表按同名网直接合并。执行联合审核前须按板实例/原理图归属拆分并校验；无法可靠拆分的对象标为 `NOT_CHECKED`。实现逐板隔离、连接模型校验和系统级网络汇总后，才适合自动化批量结论。

模板位于 [`work/system-interconnect.template.json`](../work/system-interconnect.template.json)，结构定义位于 [`schemas/system-interconnect.schema.json`](../schemas/system-interconnect.schema.json)。将模板复制到 `<DATA_DIR>/work/<工程>-<版本>/system-interconnect.json`，按当前装配配置填写。此文件是审核输入，不是原始 CAD 数据；冻结版本并在报告证据中留档。

在项目根目录执行以下 PowerShell 命令创建工作副本（已有文件保留）：

```powershell
$data = (python -B src/output_paths.py | ConvertFrom-Json).data_root
$systemDir = Join-Path $data 'work/系统名-版本'
New-Item -ItemType Directory -Force -Path $systemDir | Out-Null
$modelPath = Join-Path $systemDir 'system-interconnect.json'
if (-not (Test-Path -LiteralPath $modelPath)) {
    Copy-Item -LiteralPath 'work/system-interconnect.template.json' -Destination $modelPath
}
```

Schema 仅检查字段结构、类型、枚举、部分重复值和确认记录的引用存在性；当前没有跨记录语义校验器或自动系统网表生成器。执行时还须核对：实例/连接器/针脚/线束/工况 ID 的唯一性、引用对象真实存在、端点与原生网表一致、重复映射/短接有依据、限值范围合理。空数组或结构校验成功均不代表审核完成。

后续自动化按以下顺序实现：先按设计源与 `BOARD → SCH → SCH_PAGE / PCB` 归属拆分数据，在同一板内重建网络，以 `设计源+板实例+文档+元件ID+引脚` 定位；再实现模型的引用/重复/覆盖检查；最后按装配配置生成系统网络，并将 MB-01～MB-05 与 C-11 联合汇总。优先回归多板重复 U1/J1、同名网但不导通、异名网通过线束导通、交叉线序、同一设计多个实例、未上电板仍连接、未知映射不合并等案例。
