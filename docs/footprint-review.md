# C-10 封装与实际器件匹配审核

2026-11-08 纳入正式审核范围。`src/check_footprints.py` 可自动核对提取数据中的封装引用、经审核基线的型号/封装绑定、引脚到焊盘映射存在性、物理焊盘清单及有公差的尺寸读数。它不从库名称推断器件正确性，也不能代替厂商图纸/极性/观察面人工审核。缺少审核基线的子项输出 `NOT_CHECKED`；新增检查器不表示历史板卡已补审。执行状态沿用 [v2 判据](review-criteria-v2.md)。

## 1. 与现有检查的关系

| 检查 | 回答的问题 | C-10 如何使用 |
|---|---|---|
| A-05 原理图—PCB 网表 | 两边记录的脚/网关系是否一致 | 引用结果，但不据此证明实物脚位定义正确 |
| A-07 引脚/焊盘映射 | 逻辑脚号如何对应物理焊盘 | 复用映射清单，进一步核对确切型号的厂商定义 |
| C-09 BOM/装配变体 | 型号、值、封装与 DNP 是否一致 | 用于确定实际拟装器件及变体 |
| C-10 封装匹配 | 当前封装是否适合这个器件，且实例正确使用该封装 | 独立记录厂商依据、尺寸与极性/朝向核验结果 |

同一个错误只生成一条 finding，列出关联检查 ID。C-10 缺证据只阻断依赖该证据的结论，其他网表、电气检查继续。

## 2. 范围与检查深度

- 每个在审 PCB 元件都记录位号、完整制造商型号（含封装后缀）、库来源、符号/封装身份、版本或定义快照哈希、当前装配变体。不能确定的字段写未知。
- 常规官方封装先核型号绑定、脚号/实例映射，并检索有据可查的历史核验；相同组合的库级核验可以共享，逐实例的映射、层别与朝向仍分别记录。
- 连接器、极性器件、裸露焊盘/特殊封装、关键器件，自建/修改/来源不明或更换过的封装列为重点对象。重点原因写入记录，按下列子项补齐证据；数据不足时显式保留缺口。
- 同一型号有多个封装后缀、型号缺失、映射冲突或图纸视角不清时，列为待核对象，不能因名字相似自行认定兼容。
- 常规官方库若本次不量测尺寸、也没有可复用的尺寸证据，该子项仍为 `NOT_CHECKED`，不以“低风险”作 `NOT_APPLICABLE`。
- DNP 不自动排除：仍保留铜/焊盘检查；装配匹配是否适用依据本次变体与未来装配范围说明。

## 3. 子项与证据

| 子项 | 核查内容 | 必要证据与边界 |
|---|---|---|
| C-10.1 型号与封装绑定 | 完整 MPN、封装后缀、引脚数、库定义及实例一致 | BOM/器件属性、厂商型号表、符号/封装快照；供应商号可帮助定位，不能代替完整型号 |
| C-10.2 脚位与方向 | 厂商脚功能 → 符号脚 → 封装焊盘；pin 1、极性、顶视/底视/插接面；连接器对端 | 厂商引脚图/连接器图页码和映射记录；复用 A-07、B-10、C-08 的证据，不重复报错 |
| C-10.3 物理焊盘清单 | 预期与实际的每个焊盘、重复编号、EP、机械焊盘、孔属性与网络归属 | 预期清单来自已核封装定义，实际清单来自目标 PCB；每个物理焊盘保留独立身份，不能按脚号去重；该项不证明铜已布通 |
| C-10.4 尺寸与装配适配 | 焊盘宽长/间距、孔径/孔位、EP、定位结构及相关器件外形 | 对应型号的推荐焊盘图/尺寸公差和项目装配要求、带单位的实际测量；厂商引脚外形图与推荐焊盘图须区分；只查部分尺寸就只报告该部分 |

API/离线数据负责提供实际实例和库记录；厂商图纸负责提供器件要求。另存 `.epro2` 或第二次 API 读数可核数据一致性，但不是独立的器件正确性依据。API 没给出封装版本时记录定义快照哈希；拿不到快照就注明无法确认内容是否相同，不凭 UUID/封装名复用旧结论。

物理焊盘不能对应到逻辑脚时，先判断机械、屏蔽、EP、重复脚或来源缺失等情况，解释后再定结果。原理图引脚数不要求等于 PCB 物理焊盘数。

## 4. 执行与复用

1. 从固定版本的工程清单建立元件/型号/封装对应表；按明确的库来源证据分类，列出重点对象。
2. 检索已留档的核验记录。复用键至少包括完整 MPN/后缀、符号脚位映射、封装定义版本或哈希、厂商图纸版本/哈希及相关装配工艺条件；同名、同 UUID 均不是充分条件。
3. 为每个适用子项写要求来源，取得原始读数或图纸量测，核查并定位到位号、焊盘 ID 或图纸页。未执行/缺证据直接记 `NOT_CHECKED`。
4. 库级尺寸/脚位结果可以引用历史证据；工程实例的映射、层别、旋转及实际修改情况本轮复核。型号、映射、定义、依据或相关工艺改变时重做受影响子项。
5. 逐子项输出 `PASS / FAIL / REVIEW / NOT_CHECKED / NOT_APPLICABLE`；严重度依据实际后果，证据不足的疑点仍是 `REVIEW`。不得给整项一个掩盖缺口的总“通过”。
6. 记录覆盖数和未核清单，交叉引用原有 finding。重点对象发现项按项目流程复核，报告引用的证据复制到 `review/<工程>-<版本>-<日期>/evidence/` 留档。

### 自动结构检查

先运行 `extract.py` 生成 `pcb.json` 和 `schematic.json`，在项目目录下执行（路径换为实际路径，输出父目录须已存在）：

```powershell
python src/check_footprints.py outputs/extract/<工程>/pcb.json --schematic outputs/extract/<工程>/schematic.json --expectations work/boards/<板卡>/footprint-expectations.json --out work/boards/<板卡>/c10.json --report review/<工程>-<版本>-<日期>/c10.md
```

可复制[空白基线模板](../work/boards/_template/footprint-expectations.json)到板卡目录；空模板不会使任何子项自动通过。示例期望清单：

```json
{
  "components": {
    "U1": {
      "evidence": {"source": "review/<工程>-<版本>-<日期>/evidence/part-drawing.pdf", "document": "完整型号数据手册", "page": "封装图 42"},
      "mpn": "完整制造商型号及后缀",
      "footprint_uuid": "已核对的库定义 UUID",
      "footprint_title": "已核对的封装名",
      "pin_map": {"1": "1", "2": "2"},
      "pads": [
        {"pad_id": "库定义中的物理焊盘 ID", "number": "1", "width_mil": 20, "width_tolerance_mil": 1, "height_mil": 30, "height_tolerance_mil": 1}
      ]
    }
  }
}
```

期望值和尺寸公差必须先由人按来源证据录入，工具只验证输入值是否与提取数据一致。当前 PCB 输出由同一个库定义生成 footprint 表和实例 pads 表，因此 C-10.3 是基线对比，不是独立数据库核验。多 PCB 工程必须显式提供 `--pcb-id`；脚本会拒绝重复位号、未知基线位号及覆盖输入文件的写入。JSON 记录输入 SHA-256，Markdown 报告区分 `automatic_status`（局部机器比对）与完整子项 `status`，完整结论仍需人工补足。对照一致不会被当作完整 `PASS`：尚有人工项目时子项状态保留 `NOT_CHECKED`；已发现明确基线差异才报 `FAIL`，提取缺项报 `REVIEW`。

期望字段：`mpn`、`footprint_uuid`、`footprint_title`、`pin_map`（原理图脚号到 PCB 焊盘编号）和 `pads` 均按需填写。`pads` 按每个物理焊盘列 `pad_id`、`number`；几何核对可列 `width_mil`、`height_mil`、`hole_mil`，每个声明尺寸必须同时给显式非负 `*_tolerance_mil`。期望清单须附 `evidence.source/document/page`。尺寸基线须来自适用的厂商推荐焊盘图/公差依据，不得用未经验证的当前读数自我生成期望值。

示例仅说明字段结构，型号、ID、尺寸与公差都是占位示例，不得直接作为真实审核依据；`pads` 一旦提供必须是完整物理清单，机械焊盘允许 `number: null`，多个焊盘允许编号相同但 ID 不同。`hole_mil` 目前只接受实际读数为数值的孔径；现有 `.epro2` 提取常把孔保存为 `holeType/width/height` 对象，尚未校准其形状语义，会明确记为未检查。`--expectations` 可省略以生成缺证据清单。退出码 0 表示执行完成（不表示审核通过），1 表示发现与录入基线的差异，2 表示输入/输出错误。脚本独立运行，不依赖 EDA 客户端，也尚未接入计划中的统一 audit 引擎。

当前程序能核对基线与当前提取结果的一致性，并为差异生成带对象定位的候选 finding；它不能证明基线本身抄录正确。C-10.2 自动部分只检查声明映射的脚号/焊盘编号存在，不判断脚位功能、极性、连接器配合面或顶/底视方向；这些仍须按本规范人工检查。C-10.4 仅验证清单中提供且带公差的尺寸字段，其他尺寸继续单列未检查。自动 `FAIL` 只表示违反录入基线，finding 严重度留待复核评估，脚本不自动决定严重度或整板结论。

## 5. 报告与记录

采用 [板卡记录模板](../work/boards/_template/footprint-review.md)。分别统计元件实例数、不同型号/封装组合数、逻辑引脚数、物理焊盘数，未知分母写未知。每个子项列本次执行、引用历史证据、可判定、缺数据和不适用的对象；共享一次库级核验不代表所有实例方向均检查过。

报告范围说明示例（需按实际执行填写）：

> 本轮封装匹配纳入 <实例数> 个元件、<组合数> 个型号/封装组合。C-10.1～C-10.4 分别记录结果；<对象> 复用了 <记录/版本> 的 <子项> 证据，<对象> 的 <尺寸/脚位子项> 因 <原因> 未检查。网表一致及原生 DRC 结果另列，不作为未检查子项的通过依据。
