# 审核方式（v1 草案，判据受 v2 校订）

运行产物中的 `<DATA_DIR>` 指项目外的数据目录，查询及初始化方式见 [运行产物目录](output-directories.md)。

**日期**：2026-11-06 　**状态**：审核口径已确认（§10）；方法细节随实测迭代

> 执行判据以 [`review-criteria-v2.md`](review-criteria-v2.md) 为准。v1 清单中与 v2 冲突的固定距离/面积/相位裕度、NC 与空网集合相等、单脚网必报、net-tie 同网等规则均不得直接作为 PASS/FAIL。离线 PCB 连通脚本已区分同网/异网候选，但完整几何/层叠校准尚未完成，只能给候选结果。

## 结论

1. **采用「三层证据 + 五个阶段」**。三层证据 = CAD 原生读数（API / `PAD_NET` / EasyEDA 自带网表）、离线几何重建、人工语义与手册；五个阶段 = 数据一致性 → 电气连接 → 几何与制造 → 设计意图 → 专项。某一阶段数据不足时，该阶段的问题标「未检查 / 无法判定」，不写成结论。
2. **审核范围是原理图 + PCB + BOM**。审核依据是**器件手册 + 电气连接知识**；行业标准或公司规范只在项目明确给出时使用，并写条款号。
3. **当前阶段只做只读审核，只产出报告**。辅助画图模块后续单独立项；本阶段不调用客户端的写接口。将来做画图时，仍然先审图、单点改动、改前改后留快照。
4. **数据按命题交叉核验**：API、文件和离线重建分别说明 CAD 数据及其解释，不构成适用于所有问题的权威阶梯，也不能替代手册和实测。2026-11-06 的原型实验在「关灯神器」U7/U8（底层 LED）上发现离线焊盘坐标与铜皮网名不一致的候选，必须先与同版本 API 数据对账（见 §9）。
5. **报告只报问题，不做放行判定**。输出问题清单、覆盖率、无法判定的项；不设「可放行 / 不可放行」规则，也不替设计负责人做验收决定。
6. **审核由 agent 驱动**。脚本负责取数和确定性核对；agent 负责语义判断（电源树、接口、保护、时钟复位、器件参数）。agent 的判断必须带定位、依据和置信度；独立的 reviewer agent 复核 S0/S1 与覆盖率虚报。
7. **所有结论必须可定位**：`SCH/<页>/<位号>.<脚>`、`NET/<网名>`、`PCB/<层>/(x,y) mil`、`BOM/<位号>` 四种定位串之一；数字带单位和来源。
8. **现有 skill 可直接用的**：`easyeda-api-skill`（原生读数、定位）、`precision-afe-review`（逐网络语义审查）、`lceda-pcb`（本地规则/DRC 清单）、`jlcpcb` + `lcsc`（按需的制造/供应核对）、`datasheets`（参数核实）、`ltspice`/`ngspice`（按需仿真）。`netlist-adapter` 只验证过 `.epro`（旧格式，非 V3 `.epro2`），且工具在另一个工作区，**不能直接当本项目的机检工具**；`emc` 和 `kicad` 不能直接吃 EasyEDA 数据，只能借规则（见 §8）。
9. **开源补充按「先审后装、只读优先」**：优先评估 `jarvisluk/easyeda-pcb-design` 与 `kicad-happy`；不直接装会改图的 EasyEDA MCP/agent，除非通过 §8 的五条准入标准。

## 1. 边界

**审**：原理图连接与设计意图、PCB 网表/几何/DRC/DFM、BOM 与供应链、必要的子电路仿真；在需求允许时，另输出不绑定板厂的通用加工参数建议。

**不审 / 不能审**：
- 固件、结构、面板、线束装配。
- 没有叠层参数时的阻抗/SI 结论（样本叠层 `thickness=0`，见 §9）。
- 没有功率/电流输入时的热结论。
- 没有测试条件的 EMC 合规结论（只能做 pre-compliance 风险分析）。
- 层次原理图、总线、线束（当前提取器未支持，标 `NOT_CHECKED`）。
- 未经导出及几何核验的 Gerber 级制造一致性；同源 IPC-D-356A 网表交叉核对不能单独证明实际制造铜几何正确。

**审核依据优先级**：器件手册原文 > 电气连接知识（网络拓扑、驱动/负载、地回流、上下拉、保护）> 项目明确给出的设计规范 > 制造能力（只在需要回答制造问题时使用）。国标/行标只在项目明确指定时使用，并写出条款号。没有依据的判断标「工程判断」或「待验证」，不冒充手册结论。

## 2. 证据来源与适用边界

| 层 | 来源 | 能回答 | 不能回答 | 本项目状态 |
|---|---|---|---|---|
| T0 CAD 原生读数 | EasyEDA API：焊盘 `net/x/y`、原理图/PCB 网表、NC 标记、DRC 汇总、网络类/差分对/等长组、**设计规则表**、板框 polyline、丝印属性、图元定位 | CAD 当前数据库记录的焊盘/网表/规则/检查结果 | 实物铜层、规则是否充分、ERC/DRC 未覆盖的设计意图；DRC 具体落点（未 dump）、物理叠层参数（需 v4.2+） | 已实测可用；不是实物测量证据 |
| T1 文件读数 | `.epro2` 的 `PAD_NET`、EasyEDA 导出的 Protel 2.0 网表 | 该数据源内的连接关系、位号/封装 | 设计意图、器件参数；不等于实物测量 | 已在 2 个真实工程验证 |
| T2 离线几何 | `extract.py` 的 `schematic.json` / `pcb.json` / `netlist.json` | 导线、走线、过孔、铺铜、规则、坐标 | 设计意图；底层坐标需对账 | 可用，但坐标可信度见 §9 |
| T3 外部依据 | datasheet、标准、嘉立创能力表、LCSC 库存 | 参数、工艺下限、可采购性 | 工程取舍 | skill `datasheets` / `jlcpcb` / `lcsc` |
| T4 工程判断 | 评审者经验 | 方案取舍、风险提示 | 不能单独支撑 S0/S1 结论 | 只能作为「候选」 |

**对账规则（必须先做）**：

- T0 vs T1：核对逐 `(位号,引脚/焊盘)` 映射和网络成员分组；别名、过滤对象和导出范围差异逐项解释。未解释的数据冲突阻断依赖它的结论。
- T1 vs T2：原理图重建与 EasyEDA Protel 网表须比较全部引脚成员分组；自动网允许改名但不允许跳过拓扑。当前校验器已补共有引脚拓扑检查，独有引脚、别名及特殊映射仍须解释。
- T0 vs T2：焊盘坐标逐点对账，容差由字段精度、坐标变换和校准样本确定；旧 `1 mil` 仅为筛查值。误差接近规则余量或坐标未确认时，相应几何检查降级为「候选」。
- 数据层不一致本身就是一条 finding（数据类），要写进报告，不能静默丢弃。

## 3. 五个阶段（不是放行门禁）

审核分阶段推进，但阶段之间不是「通过/不通过」的验收关卡。数据不足时，报告如实写「未检查 / 无法判定」，不替设计负责人做放行决定。

| 阶段 | 名称 | 输入 | 产出 | 数据不足时 |
|---|---|---|---|---|
| 0 | 数据一致性 | `.epro2`、API 快照、两份网表 | 可信数据 + 数据类问题清单 | 先修数据/解析；只阻断依赖该数据的结论，其他可信输入支持的检查可继续 |
| 1 | 电气连接 | 原理图网表、PCB 网表、NC 标记 | B 类问题清单 | 未支持项标 `NOT_CHECKED`（如层次/总线） |
| 2 | 几何与制造 | `pcb.json`、规则、项目制造要求 | D/F 类问题清单 | 坐标未对账的元件，其几何问题降为「候选」 |
| 3 | 设计意图 | 设计意图卡、datasheet、C 类清单 | C 类问题清单 + 每条判断的依据 | 缺手册/意图的部分标「待验证」 |
| 4 | 专项与汇总 | E/G 类（按需） | 专项问题 + 覆盖率 + 汇总报告 | 数据不支持就写「无法判定」及所需数据 |

**覆盖率只报告、不设门槛**：覆盖率用来说明这批结论的边界（哪些网/焊盘/检查真的看过），不作为验收标准；未覆盖项必须在报告里逐条列出。

### 3.1 板型分档（决定查多深）

同一套清单不能对所有板子平均用力。先给板子分档，再按档位裁剪：

| 档 | 典型板子 | 默认检查 | 追加 | 按需求裁掉（写明理由） |
|---|---|---|---|---|
| **A 简单数字/电源** | 小家电、灯控、转接板 | A + B + D + F + C 通用项 | E-02、E-07 | E-04/E-05/G-03（无高速） |
| **B MCU/混合信号** | ESP32/STM32 开发板、传感器板 | A + B + D + F + C 全量 | E-01、E-02、E-07、G-01 | E-05（无差分）/G-03（无阻抗要求） |
| **C 高速/射频/精密** | USB/HDMI/Ethernet、RF、精密 AFE | A + B + D + F + C 全量 | E-01~E-07、G-01~G-03；需要叠层/阻抗数据 | 缺叠层时相关结论标「无法判定」，不猜 |
| **D 高压/大功率/隔离** | 电源、电机驱动、隔离接口 | A + B + D + F + C 全量 | E-08、E-09、G-01；需要安规/爬电要求 | 缺安规数据时相关结论标「无法判定」，不猜 |

档位由第 0 步的设计意图卡和项目需求确定，写进报告头。报告里要写「按 X 档审核」，让读者知道边界。

**语义审查的覆盖优先级**（不是平均抽样）：
1. 优先：所有电源/地网、时钟/复位/启动、对外连接器、保护器件、稳压器外围。
2. 优先：引脚数多或有多个驱动的网（易出总线/方向错误）。
3. 其余：普通 I/O、指示灯、测试点；可以抽样，但抽样规则和样本量写进报告。

### 3.2 独立性

- 脚本给事实，agent 做判断；**做判断的 agent 不应该同时是改图的人**。
- 汇总前用独立 reviewer agent 做第二遍：只读，拿 `audit.json` + 报告 + 原始快照，不参考改图过程的解释。
- 第二遍只解决三件事：S0/S1 是否成立、有没有漏项、覆盖率有没有虚报。

## 4. 审核流程

### 第 0 步：受理与冻结

记录并写进报告头：工程名、版本/日期、`.epro2` SHA256、编辑器版本、原理图页数、PCB 数、BOM 版本、审核范围（原理图 + PCB + BOM）、依据来源、只读连接是否可用。

**尽量拿到「设计意图卡」**（模板见 `review-checklist.md` §10）：电源输入/各路电压电流、连接器对端与线序、关键器件型号、项目制造要求、环境与安规要求、已知问题。缺卡时，agent 仍可做通用电气审查，但报告标「意图未知」，相关结论降为「候选」。

### 第 1 步：取快照

```bash
cd projects/epro2-辅助绘制及审核
python src/extract.py <工程.epro2>            # 离线：index/schematic/pcb/netlist/summary
python src/eda.py up                          # 确保 bridge 可用
python src/eda.py status                      # 确认当前工程/打开页
```

API 侧至少落盘：原理图网表、PCB 网表、全部焊盘（`num/net/x/y/layer`）、元件清单、**原理图 ERC 与 PCB DRC 原始结果**、**规则配置/启用规则/规则单位**、**激活文档/板名/启用层/工具版本**、NC 标记、图元定位所需 ID。过程产物放 `<DATA_DIR>/outputs/audit/<工程>/<版本>/`（临时，可清）；**定稿报告引用的输入快照复制到 `<DATA_DIR>/review/<工程>-<版本>-<日期>/evidence/` 留档**，与报告（同目录 `report.md`）一起提交。这个 evidence 目录算「审核档案」，不算临时文件；如与项目目录约定冲突，按项目负责人确认的路径执行。

> 无 headless：一次只能取当前激活文档；PCB 与原理图要分别 `activateDocument`。切换前确认没有未保存改动。

多 PCB / 多板系统另按[多板系统联合审核](multi-board-review.md)冻结板卡实例与版本、逐板取证，并以 `system-interconnect.json` 的证据映射建立系统网络。当前提取器的 comparison 仅针对元件最多的 PCB，且原理图网表全工程汇总；重复位号碰撞未解决前，禁止将其当作多板逐板对比或板间连通结论。

### 第 2 步：数据一致性（阶段 0）

```bash
python src/validate_netlist.py <工程目录>/netlist.json <EasyEDA导出的.net>
```

- 原理图重建 vs EasyEDA 网表：检查命名和全部网的成员分组；新版脚本已补自动网拓扑，报告需同时列未匹配成员及其处理，不能只引用返回码。
- 离线 vs API 网表：网集合、逐引脚一致。
- 离线 vs API 焊盘坐标：逐点对账（**本项目的必做项**）。
- 原理图↔PCB `comparison`：`mismatch_details`、`only_in_schematic`、`only_in_pcb`、`net_mismatches` 逐条解释。

数据不一致时，先修数据；只阻断依赖该数据的结论，其他可信输入支持的检查可继续，并在报告里写明依赖关系。

### 第 3 步：确定性检查（阶段 1/2 的机器部分）

按 `review-checklist.md` 的检查库执行，产物 `audit.json`：

- 每条检查有 `id / status / denominator / covered / skipped_reason`。
- 每条 finding 有稳定 ID、定位串、证据引用、严重度、状态、依据类型。
- 脚本只报事实，不写「建议重新设计」这类判断；判断交给第 4 步的 agent。

**首批 MVP 检查**（见清单 §8）：A-01~A-05、B-01~B-03、B-07、D-01、D-04、D-05；F-01 仅在项目指定板厂时启用。C-10 同轮使用 `src/check_footprints.py` 作局部自动比对，人工/agent 补核剩余项；自动比对覆盖与完整子项状态分别统计。目前独立命令可运行，统一 `src/audit/` 引擎仍待实现。

### 第 4 步：agent 语义审查（阶段 3）

用 `precision-afe-review` 的逐网络方法作为 agent 的作业指导：电源 → 地 → 接口/上下拉 → 时钟复位 → 保护 → 通信 → BOM/扫尾。输入优先 `netlist.json`（保留未连接脚），用 EasyEDA Protel 网表交叉核对。

**agent 的分工方式**（可按板子大小并行）：

| agent | 负责 | 输入 | 输出 |
|---|---|---|---|
| 电源/地 agent | 电源树、稳压器外围、地策略、退耦、关键网络供电与电荷预算 | 网表、BOM、datasheet、逐负载工况/并发关系、PCB 路径依据 | C-01/C-02/C-11、B-03、E-01/E-02；必要时关联 G-01 |
| 接口 agent | 连接器 pinout、电平、上下拉、差分/保护 | 网表、意图卡、对端资料 | C-03/C-05/C-06/C-08 |
| 时钟/复位/启动 agent | 晶振、复位、BOOT/模式脚 | 网表、MCU datasheet | C-04、B-05 |
| PCB 几何 agent | 线宽/间距/连通/过孔/铺铜/丝印 | `pcb.json`、规则、API 读数 | D 类复核 |
| BOM agent | 型号/封装/极性/替代料/DNP | BOM、`lcsc`、datasheet | C-09、F-02 |
| 封装审核（由 BOM 与 PCB 审核协作） | 型号绑定、厂商脚位/观察面/尺寸与实际焊盘 | 完整 MPN、厂商图纸、库定义快照、PCB 实例；见 `footprint-review.md` | C-10；复用 A-07/C-09 证据，缺失子项单列 |
| 汇总 agent | 去重、冲突消解、定位串统一、覆盖率核对 | 以上全部 | `audit.json` + 报告草稿 |
| 独立 reviewer agent | 只读复核 S0/S1、查漏、查覆盖率虚报 | 快照 + 报告 | 复核意见 |

**agent 做判断时的纪律**：
- C-11 在 C-01/C-02 后按[供电与电荷预算审核](power-charge-budget.md)执行，先列关键电源轨及工况，再填写板卡 `power-charge-budget.md`。持续供电、瞬态电荷、路径压降、周期恢复分别给结果；PCB 审核提供经校准的路径依据，独立 reviewer 复核供电边界、并发假设、有效容量和覆盖缺口。当前按证据计算/按需仿真，自动预算检查器待实现。
- C-10 按[封装匹配审核](footprint-review.md)执行，自动结构检查使用 `src/check_footprints.py`，期望基线必须来自 BOM/厂商资料核验；记录使用 `work/boards/_template/footprint-review.md`。极性、器件功能、观察面、装配适配等不能从提取数据自证的内容仍由 agent 按证据逐项核验，不能把官方库来源当作通过。
- 可以判断，但每条判断必须给：定位串 + 证据（文件字段 / datasheet 页码 / 计算式）+ 依据类型 + 置信度。
- 不许凭记忆给引脚号、地址、阈值；查不到就写「待验证」。
- 不许把「没查」写成「没问题」；未支持的模块写 `NOT_CHECKED`。
- 不用 PDF 渲染图当连接依据；连接以网表为准。
- 冲突时保留双方意见，标「需人工裁决」，不要悄悄合并。

**注意语义差异**：EasyEDA 网表不含未连接脚、不含 `Convert to PCB: no` 的元件；`netlist.json` 保留。两者数量差不是错误，但要在报告里解释。

### 第 5 步：专项（阶段 4，按需）

- **制造/DFM**：项目指定板厂/工艺时，按该厂能力核对；未指定时可按 [`manufacturing-guidance.md`](manufacturing-guidance.md) 输出需求驱动的通用加工参数建议。建议必须写明工况、假设、依据和复核条件，不得写成板厂能力通过或加工保证。
- **供应链**：需要采购时才查 `lcsc` 库存/基础库/替代料。
- **EMC**：用本项目几何 + `emc` skill 中可回查原始依据的项（地平面/回流、连接器滤波、时钟走线等）；固定距离/面积阈值不直接采用。该 skill 目前只吃 KiCad 分析器 JSON，需适配或移植（§8）。
- **仿真（按需触发，不默认全跑）**：见 §4.1。
- **热/隔离/高速**：没有功率、叠层、阻抗数据时，只做风险提示，不下结论。

#### 4.1 仿真

**定位**：仿真属于「计算」级证据，强于工程推断，弱于实测；不能替代 datasheet 的引脚/参数核对，也不能替代 DRC 和几何检查。

**触发条件（四条同时满足才跑）**：

1. 结论依赖一个 datasheet 没直接给出的数；
2. 有可信模型（厂商 SPICE 模型，或可验证的等效参数）；
3. 结果会改变审核意见或设计取舍；
4. 跑之前能写清有项目/器件依据的通过判据与工况（相位裕度、纹波或延时目标等），不默认采用统一 45° 门限。

四条不满足时，报告写「不需要仿真」及理由；缺模型导致无法判断时写 `NOT_CHECKED`，不拿模型不明的 deck 凑结论。

**适用**：

| 场景 | 典型问题 |
|---|---|
| 稳压器环路 | 相位裕度、输出电容 ESR、负载瞬态 |
| 分压/基准/比较器 | 阈值、容差、源阻抗影响 |
| 滤波/保护 | RC 截止、TVS 钳位、保险丝 I²t、浪涌 |
| 时序 | 上电顺序、使能/复位延时、软启动 |

**不适用**：

- 网表、连通性、封装、BOM、DRC（数据核对问题）。
- 无叠层、无 IBIS 的信号完整性（样本叠层参数为 0，跑出来是假精度）。
- EMC 合规结论（只能做趋势分析，合规要实测）。
- 用仿真代替 datasheet 核对。

**执行要求**：

- 先读 `spice-bench-craft` 定测试台，单点用 `ltspice`/`ngspice`，批量/扫参用 `spice-experiments`。
- deck、模型、结果放 `<DATA_DIR>/outputs/audit/<工程>/<版本>/sim/`；报告引用时把关键 deck 和 `.MEAS` 复制到 `<DATA_DIR>/review/<工程>-<版本>-<日期>/evidence/`。
- 每条结果记录：模型来源与版本、测试台、激励条件、测量点、单位、corner/温度（跑了的才写）。
- 报告写「判据 → 仿真值 → 结论（通过/不通过/无法判定）」；没跑的不写数值。
- 仿真不通过时给定位串和波形/测量文件，不写成「建议重新设计」这类空话。

### 第 6 步：汇总报告（阶段 4）

一次审核一个目录：`<DATA_DIR>/review/<工程>-<版本>-<日期>/`，交付完整报告 `report.md`、简明报告 `simple-report.md` 和引用证据 `evidence/`。先完成 §6 的完整报告，再按 [简明报告模板](simple-report-template.md) 提炼简明版。**简明版只为阅读提炼，不新增结论；范围、严重度、状态、假设和未判定项必须与完整报告一致，不给放行结论。** 每条 S0/S1 必须能被第二个人按定位串复现。

### 第 7 步：复审（改版后；当前阶段以只读为主）

- 当前阶段只做只读复审：拿新版 `.epro2`，重跑 A 类和受影响的检查，比 `audit.json`。
- 将来做辅助画图时：单点改动 → 改前快照 → 单点操作 → 读回验证 → 改后快照 → diff；不批量改已定稿图纸。
- finding 状态从「候选」转「已关闭」要有新证据；版本对比看 finding ID 集合差异，不靠肉眼比报告。

## 5. 判定规则

### 5.1 严重度（只用于排序，不是放行规则）

| 严重度 | 含义 | 例子 |
|---|---|---|
| **S0 严重** | 潜在后果：核心功能失效、损坏器件、安全风险或制造必失败（严重度只看后果，证据强弱写在状态/依据/置信度） | 必需电源接错档、关键网短路/开路；空网焊盘或 DRC warning 本身不自动定 S0 |
| **S1 重要** | 大概率影响功能/可靠性/可制造性 | 漏上拉、退耦不足、ESD 缺失、线宽余量不足、连接器脚序可疑 |
| **S2 建议** | 规范/可维护性/精度余量 | 命名不一致、丝印不清、测试点缺失 |
| **S3 提示** | 优化项 | 布局可更紧凑、注释补充 |

严重度只回答「先看哪个」，不回答「能不能出货」。报告不设总体放行结论；是否接受风险由设计负责人决定。

### 5.2 状态与依据

| 字段 | 取值 | 规则 |
|---|---|---|
| `status` | 已核实 / 已确认 / 候选 / 需人工 / 无法判定 / 不适用 | 原始读数证明事实，不自动证明事实违反要求；已确认需有明确要求和可复核的冲突证据 |
| `basis` | 实测 / 计算 / 手册 / 推断 | **S0/S1 不允许只靠「推断」**；只能降为候选或补证据 |
| `confidence` | 高 / 中 / 低 | 与 basis 独立；数据不完整时不能给「高」 |

**v2 结果与报告 `status` 的映射**（v2 是检查结果，`status` 是 finding 状态）：

| v2 结果 | 报告 `status` | 含义 |
|---|---|---|
| `PASS` | 已核实（无问题） | 要求明确、输入完整、检查覆盖到要求范围，未发现违反 |
| `FAIL` | 已确认 | 可信输入上有可复核的违反证据 |
| `REVIEW` | 候选 / 需人工 | 可疑或要求不明确，尚不能定 `FAIL` |
| `NOT_CHECKED` | 无法判定 / 未检查 | 缺数据或工具能力不足 |
| `NOT_APPLICABLE` | 不适用 | 有书面理由说明为何不适用 |

`PASS` 不是「脚本没报错」；`NOT_CHECKED` 不计入通过。严重度与状态独立：候选也可以标潜在 S0/S1。

### 5.3 定位串

- `SCH/<页名或页号>/<位号>.<脚号>`，例：`SCH/Camera/FPC1.19`
- `NET/<网名>`，例：`NET/VCC_3V3_MAIN`
- `PCB/<层>/(<x>,<y>) mil`，例：`PCB/Top Layer/(1234.5,-567.8) mil`
- `BOM/<位号>`，例：`BOM/U3`

API 的 `navigateToCoordinates` / `highlightNet` / `selectNet` 用同一套坐标和网名，报告里的定位可以直接点过去。

### 5.4 finding ID

`sha1(check_id | 定位串 | 归一化证据)[:12]`。同一问题跨版本保持稳定，便于 diff；时间戳不进 ID。

### 6.1 简明报告

本要求适用于单板、多板联合审核以及用户限定范围的审核（如仅原理图）；简明版沿用实际范围，不因模板而扩大检查范围。交付前逐项核对两份报告的对象/版本、统计口径、S0/S1 是否遗漏、状态和关键假设，并验证相互链接及 finding 定位；如有 `audit.json`，同时与其核对。简明报告模板中的填写提示应在定稿时替换或删除。

## 10. 已确认的审核口径（2026-11-06）

1. **范围**：原理图 + PCB + BOM。
2. **依据**：器件手册 + 电气连接知识；项目另有规范/国标时按其条款执行。
3. **当前阶段**：只读审核，只产出报告；辅助画图模块后续单独立项，本阶段不调用写接口。
4. **报告形态**：只列问题、覆盖率、无法判定的项；**不制定放行规则**，不替设计负责人验收。
5. **制造核对**：按项目需求具体分析；项目没指定板厂/工艺时，可以输出需求驱动的通用加工参数建议，但必须标注假设、依据和复核条件，不默认套某一家能力值。
6. **审核方式**：agent 驱动，agent 可以做语义判断；独立的 reviewer agent 复核 S0/S1、漏项和覆盖率。

**仍需项目侧提供（不阻塞启动）**：

- 每个项目的设计意图卡（电源/接口/关键器件/环境/制造要求）。
- 需要核对的连接器对端资料、结构限高、安规/隔离要求。
- 报告严重度是否沿用 S0~S3 这套排序，还是项目有自己的优先级口径。
