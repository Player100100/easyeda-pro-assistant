# finding 生命周期（轻量版）

> 目的：让每个问题从「可疑」到「关闭」都有记录，复审时能 diff，不靠记忆。
> 适用：本项目的只读审核；不是放行流程。

## 1. 状态

| 状态 | 含义 | 对应 v2 结果 |
|---|---|---|
| `候选` | 看到可疑，但要求或证据不足 | `REVIEW` |
| `已确认` | 有明确要求 + 可复核的违反证据 | `FAIL` |
| `待复核` | 已改图或补了证据，等待复审 | — |
| `已关闭（修复）` | 新版本复核通过，有证据 | `PASS` |
| `已关闭（接受风险）` | 设计负责人书面接受，记录范围和有效期 | — |
| `不适用` | 有理由说明该检查不适用于本板 | `NOT_APPLICABLE` |

`NOT_CHECKED` 不是 finding 状态，是覆盖项：写进覆盖率，不写进 finding 表。

## 2. 允许的流转

```text
候选 ──补要求+证据──> 已确认
候选 ──说明理由────> 不适用
已确认 ──改图/补证据──> 待复核
待复核 ──复审核通过──> 已关闭（修复）
已确认 ──负责人接受──> 已关闭（接受风险）
任意状态 ──出现反证──> 候选（重新打开）
```

规则：

- `候选 → 已确认` 必须新增：明确要求及来源 + 可复核证据。不能只凭“看起来不对”。
- `已确认 → 已关闭（修复）` 必须有新版快照或新读数，不能只凭口头说改了。
- `已关闭（接受风险）` 必须记录：谁接受、影响范围、有效期、复审日期。
- S0/S1 不允许 agent 自行关闭；只能由人接受风险或新证据证明修复。
- 关闭的 finding 不删除，保留历史，供复审 diff。

## 3. 每条 finding 至少要有的字段

| 字段 | 说明 |
|---|---|
| `id` | 稳定 ID，跨版本不变 |
| `check` | 检查项，如 B-04 |
| `status` | 上表状态 |
| `severity` | S0~S3；表示潜在后果，不表示已确认 |
| `locator` | `SCH/`、`NET/`、`PCB/`、`BOM/` |
| `fact` | 看到了什么，带读数/单位 |
| `requirement` | 应该满足什么 |
| `source` | 要求来源：手册页码/项目要求/标准/板厂能力 |
| `evidence` | 证据文件、字段、截图、计算式 |
| `close_condition` | 补什么证据/谁确认后可以关闭 |
| `history` | 状态变更记录：日期、从什么到什么、原因 |

## 4. 复审 diff

复审时只比较 finding 的 `id` 集合和状态：

- 新增：新版本出现的问题
- 仍在：未处理
- 已关闭：有修复/接受风险记录
- 重新打开：之前关闭，但新证据表明仍存在

不要靠肉眼比两份报告。

## 5. 例子

| 阶段 | 记录 |
|---|---|
| 候选 | `F-001`：C8 到 U5.4 约 12.4 mm，比其它去耦远；要求未查 |
| 已确认 | 查到 U5 手册布局建议：去耦应尽量靠近电源脚；当前布局不满足，标 `FAIL` |
| 待复核 | 设计方移动 C8，提交新版 `.epro2` |
| 已关闭（修复） | 新版复算 C8 到 U5.4 约 3.1 mm，满足手册建议；记录新快照 hash |
| 已关闭（接受风险） | 若设计方决定不改，记录“接受 12.4 mm 布局风险”，影响范围/有效期/批准人 |

```json
      "source": "U5 datasheet, rev/date, page/table",
      "evidence": ["outputs/.../pcb.json", "datasheets/U5.pdf#page=..."],

        {"date": "2026-11-08", "from": "new", "to": "候选", "reason": "首轮扫描"}
      ]
    }
  ]
}
```
